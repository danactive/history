## Context

See proposal.md for motivation. The visited server route obtains `CountryVisit[]` through `getVisitedData`, renders chronological country groups, and builds existing filter-query links. Mapbox and react-map-gl are installed, and the photo map already uses a public token. Installed Next.js guidance requires browser-only dynamic imports to originate within a client component.

No existing application offline-mode setting or browser online-status integration was found in `src`, `app`, or `config.json`. Treat offline as lack of internet access while the local app remains reachable; browser offline detection and basemap network failures activate vector-only rendering. This does not add an offline application shell for an unreachable server.

The working tree contains a candidate implementation in `src/components/VisitedMap`, route integration, a shared token module, and country GeoJSON files. It has passed focused region/scroll tests and browser checks in the preceding implementation turn. This plan captures the intended contract and identifies acceptance work still needed; it makes no further implementation changes.

## Goals / Non-Goals

**Goals:** Keep server-rendered visit content intact, confine interactive state to the map wrapper, retain all four countries' boundary assets and visited overlays, and make country selection deterministic in both scroll directions.

**Non-Goals:** No mobile layout, mobile breakpoint, or mobile-specific reading line. No metadata schema migration, geographic inference from cities, additional map subscription, separate visit database, or changes to the photo-map camera/filter behavior. See proposal.md for product scope.

## Decisions

1. **Server list inside a client layout wrapper.** Pass the rendered list as children and existing country data as serializable props. Lazy-load the map in that client wrapper with SSR disabled. This preserves existing server data access and links rather than moving the entire route into the client.

2. **Sticky panel with normal document scrolling.** Use a desktop grid with the map on the right and `position: sticky`. Keep this side-by-side layout when resizing the desktop window; do not introduce a stacked mobile layout. A fixed overlay or nested scroll container would complicate keyboard navigation and page scroll restoration. Keep attribution visible locally because global CSS hides Mapbox controls for the existing photo map; show explicit zoom buttons but omit compass controls.

3. **Reading-line selection.** Mark country heading elements with a data attribute, evaluate supported heading positions in document order, and select the last heading above the reading line. Start with 100px from the viewport top for the desktop reading line. Use passive scroll listeners and animation-frame coalescing, with resize/content-size observation and cleanup. Position evaluation handles skipped sections and reverse scrolling more predictably than relying solely on individual intersection callbacks. Retain the last supported country through unsupported sections; the panel title and a subtle marker on the corresponding country list item make that choice explicit. Mirror active state into a scoped data attribute/class and an accessible current-state annotation without changing link destinations or list order. These are proposed defaults, not additional user requirements.

4. **Local, country-specific GeoJSON.** Use public-domain Natural Earth 5.1.2 Admin 1 geometry (47 Japan, 51 USA including DC, 13 Canada, 32 Mexico including Mexico City). Keep attribution and provenance in `public/maps/visited/README.md`. Retain ISO IDs, display names, and aliases; explicitly name DC District of Columbia to avoid the source's Washington collision. The four assets are bundled locally as compact GeoJSON. Load all four when the map mounts, cache successful responses, and keep each source/layer mounted independently of the active heading. Compute visited flags from the gallery data for each country; countries with no visits retain neutral boundaries. A failed country asset must not hide other successfully loaded overlays. Premium Mapbox boundary tiles would add entitlement requirements; runtime third-party GeoJSON would add an avoidable dependency.

5. **Conservative matching.** Normalize case, accents, whitespace, punctuation, and known prefecture suffixes. Match canonical names/ISO codes first, then unique aliases within that country. Use IDs to deduplicate; surface unknown or ambiguous values instead of guessing. Do not reuse the photo-count threshold for search options: every recorded region visit is eligible for highlighting.

6. **Globe with a shared starting overview.** Configure `projection="globe"` explicitly on the persistent map and local offline style, matching the projection used by the album maps. Globe supports the standard GeoJSON fill and line layers needed here; the planned DOM labels and leader-line overlay do not require unsupported custom WebGL layers. Start at a low shared overview zoom (initial candidate 1.5, verified visually), allow manual zoom with the same native Globe zoom behavior as album maps, and preserve the user's current zoom on automatic pans. Do not change projection per country. The online basemap remains dark; matching the album projection does not require switching to satellite imagery. See [Mapbox Globe documentation](https://docs.mapbox.com/mapbox-gl-js/guides/globe/).

   Only the front-facing hemisphere is visible. Keep all four countries' sources mounted, but render labels and leader lines only for anchors on the visible globe surface and within the viewport. Recalculate horizon visibility during pans, zooms, and resize so far-side text never appears through the globe. Changing the center turns the globe toward the selected country while bearing and pitch remain zero; this is compatible with disabling user bearing/tilt gestures.

7. **Automatic pan-only camera with manual zoom and persistent layers.** Reuse the existing token and dark basemap. Set a shared initial zoom with bearing and pitch zero; select a center for each country and use `panTo` (zero duration for reduced motion). Remove `fitBounds` on country changes and resize. Resize the canvas while retaining zoom and center. Enable wheel and double-click zoom over the map; retain ordinary page scrolling over the left list and disable pitch/rotation gestures. Allow drag panning and deliberate zoom through explicit accessible plus/minus controls, including keyboard activation; retain mouse wheel and double-click zoom as well. A country change must preserve the current manually chosen zoom for the entire pan. Keep all country sources and visited flags in place while panning. Offscreen features remain loaded and appear as soon as they enter the visible hemisphere and viewport; “always display” does not mean forcing all four countries into the viewport simultaneously. Delayed responses add only their own country's source, never replace another country's data or move the camera. Abort outstanding fetches on unmount and keep loading/error state independent per country.

8. **Offline vector-only rendering.** Initialize with a minimal local Mapbox style (plain background, explicit Globe projection, no remote sources, glyphs, or sprites) when the browser reports offline. Listen for online/offline changes; loss of connectivity removes the online basemap and keeps all local outlines, visited fills, and labels. Because `navigator.onLine` may remain true on a local network without internet, basemap network failure also falls back to the local style. Do not interpret this expected fallback as a failure of the whole map. Preserve camera state and reattach persistent vector layers across style changes. While in offline mode, issue no new Mapbox tile, style, sprite, or glyph requests; stop outstanding basemap loading as part of the transition. Add a keyboard-accessible Basemap switch with clear on/off state. Track user preference separately from network availability: effective basemap visibility requires both the preference and connectivity. Turning it off immediately selects the local style and stops basemap loading while retaining the camera and overlays. Keep the preference for the current page session across country and connectivity changes; reconnect only restores tiles if the preference is on. Show an offline/fallback indication so an enabled preference does not falsely imply tiles are available. Local geometry/label assets must work on an offline first visit to the running local app, without a previously warmed Mapbox cache.

9. **Centered labels with collision handling and local fonts.** Prepare one label anchor per administrative division alongside the boundary assets, using an interior visual-center point (pole of inaccessibility) in the largest/main land polygon rather than a raw centroid that can fall in water or outside a concave region. Validate and curate anchors for archipelagos and dateline geometry. Render DOM labels in a map overlay using system fonts, initially horizontally and vertically centered on that point, above the vector fills; this avoids a remote glyph service and keeps the same labels online and offline. Label every division, visited or unvisited, with full names where they fit, postal abbreviations for US/Canada where necessary, and short Japanese names or unambiguous ISO subdivision codes for very small prefectures. Keep the full name available on hover and keyboard focus, and use a subtle contrast halo/background. Do not silently drop labels through symbol collision suppression. Exclude globe-occluded anchors from labels, focus targets, and leader lines before collision layout. Measure screen-space label boxes, place full names centered where they fit, then substitute abbreviations. If abbreviated boxes still collide, displace the text a short distance into available nearby space and draw a leader line back to the unchanged interior anchor. Recompute placement after pan/zoom/resize using deterministic ordering and stable offsets to avoid jitter. The region anchor remains inside the polygon even when its label moves outside. Manual zoom provides further detail without automatic camera changes.

10. **Coverage totals.** Compute each numerator from matched unique region IDs, never photo counts or duplicate aliases. Use denominators 47 for Japan, 51 for USA including DC, 13 for Canada including territories, and 32 for Mexico including Mexico City; label these inclusions explicitly (for example, “8 of 51 states / DC visited”). When boundary data is unavailable, show unavailable/loading status rather than a fabricated zero. Retain amber fill and a stronger outline for visited regions, with neutral thin boundaries for unvisited regions, so color alone is not the only cue.

## Risks / Trade-offs

- [Natural Earth is generalized cartography] → Treat it as a coverage visualization, document its provenance, and avoid presenting borders as survey precision.
- [A shared starting overview makes Japan and small regions appear smaller] → Keep automatic pans at the current zoom, offer explicit manual zoom, and verify coverage at overview and detail scales.
- [Online basemap access may fail even when the browser reports online] → Fall back to a local vector-only style; verify offline first load and connectivity transitions without remote fonts or cached basemap resources.
- [Centered labels crowd small prefectures at overview scale] → Abbreviate first, then use short leader lines; retain full-name hover/focus text and verify dense regions at overview and manually selected detail zooms.
- [A geometric centroid can fall outside a region] → Use validated interior anchors and curated exceptions for islands and dateline shapes.
- [Alias collisions can create false visits] → Prefer canonical matches, reject ambiguous aliases, and regression-test Washington versus DC.
- [Concurrent boundary loads can finish out of order or fail independently] → Test that each result updates only its own persistent source, preserves other overlays, and never changes the active camera or summary.
- [Globe hides the far hemisphere] → Keep every source loaded, cull occluded labels/leader lines, and verify Canada–USA–Japan pans in online and vector-only modes.
- [Last supported heading may not reach the threshold on a short page] → Verify short-list behavior against the first-country fallback and selection contract; do not add artificial scroll space without a demonstrated need.

## Migration Plan

No data migration is needed. Reconcile the existing candidate against the delta spec, remove its mobile CSS breakpoint and mobile-specific reading-line branch, replace Mercator and country-fitting with Globe, automatic pan-only navigation, and manual zoom, retain all overlays, add offline vector-only rendering with a Basemap toggle, collision-aware centered labels, an active-country indicator, and coverage totals, finish missing acceptance coverage, and run the verification tasks before marking implementation complete. Ship route/component changes together with the four boundary assets and local label anchors/names. Rollback restores the list-only route and removes the new map components/assets; original media and XML remain unchanged.


Follow-up implementation: DOM labels remain mounted independently of basemap style readiness; replacing a style must not reset their visibility through an event/effect race. Mexico uses a fourth local dataset containing 31 states and Mexico City. Country matching accepts Mexico/México, while region matching keeps State of Mexico separate from Mexico City and retains legacy DF/MX-DIF aliases. Exclude Natural Earth's unnamed MX-X01~ feature from the administrative denominator.


Location validation: load boundaries once in the page wrapper and share them with the map and a validation section below the list, reachable from a link at the top. Validate known administrative names for the four supported countries, plus normalized duplicate names throughout the list. Suggest close spellings conservatively using edit distance on names of at least four characters; never paint fuzzy guesses. Preserve list names and filters, but combine region inputs for country aliases before deduplicating map coverage by feature ID. Exact repeated visit names are already aggregated upstream and are not a duplicate-photo warning.
